|                          |                                                                                                      |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| Status                   | **DRAFT** (S03). Becomes **FROZEN** after validation on real phones and an ACR1252U reader in S01    |
| Reference implementation | `packages/contracts/src/tap/` (TypeScript; Node helpers in `node.ts`)                                |
| Test vectors             | `packages/contracts/tap-protocol/vectors.json`, shared by the API, kiosk FakeReader and Kotlin tests |
| Summary                  | [ARCH §6](../../plans/ictu-labpass/01-architecture.md)                                               |

## 1. Encodings

| Item                                          | Encoding                                                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| UUID (`credentialId`, `kioskId`, `sessionId`) | 16 raw bytes in RFC 4122 network order, i.e. the hex digits of the canonical string, left to right         |
| `ts`                                          | uint64, big-endian, Unix epoch **milliseconds**                                                            |
| `nonce`                                       | 16 random bytes generated by the **server** (kiosk challenge pool). Offline mode: generated by the kiosk   |
| Signature                                     | ECDSA over P-256 with SHA-256, **ASN.1 DER** (`SEQUENCE { INTEGER r, INTEGER s }`), 8–72 bytes             |
| Public key                                    | DER `SubjectPublicKeyInfo`, curve `prime256v1` only                                                        |
| Text fields                                   | base64url **without padding** (RFC 4648 §5). Decoders reject `=`, `+`, `/` and non-canonical trailing bits |

## 2. HCE application

| Item            | Value                                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| AID             | `F0 49 43 54 55 4C 50 01` (proprietary range `F`, ASCII "ICTULP" + version 1)                                    |
| Android service | `HostApduService`, category `other`, `android:requireDeviceUnlock="true"`                                        |
| Key             | Android Keystore P-256, non-exportable, `setUnlockedDeviceRequired(true)`, StrongBox if available, otherwise TEE |

### 2.1 SELECT (kiosk → phone)

```
00 A4 04 00 08 F0 49 43 54 55 4C 50 01 00        (14 bytes)
```

| Phone state                       | Response                                      |
| --------------------------------- | --------------------------------------------- |
| Enrolled                          | `01` ‖ credentialId (16) ‖ `90 00` (19 bytes) |
| Not enrolled / credential removed | `6A 82`                                       |
| Any other AID selected            | `6A 82`                                       |

### 2.2 SIGN (kiosk → phone)

```
80 10 00 00 28 ‖ nonce (16) ‖ kioskId (16) ‖ ts (8) ‖ 00        (46 bytes)
```

The phone signs **M = ASCII "ICTU-LP1-HCE" ‖ credentialId ‖ nonce ‖ kioskId ‖ ts** and answers:

| Outcome                                         | Response                |
| ----------------------------------------------- | ----------------------- |
| Success                                         | DER signature ‖ `90 00` |
| Key unavailable (phone locked, key invalidated) | `69 82`                 |
| Lc ≠ `0x28` or total length ≠ 46                | `67 00`                 |
| Proprietary class with INS ≠ `0x10`             | `6D 00`                 |
| CLA not `00`/`80`                               | `6E 00`                 |

The signature must be computed off the main thread, and the result returned with `sendResponseApdu`. The service never needs the React Native runtime.

## 3. Scan-the-Kiosk

### 3.1 Kiosk challenge QR (shown on the kiosk screen)

```
LPK1.<kioskId: b64url(16 bytes)>.<nonce: b64url(16 bytes)>
```

### 3.2 Device key (Android app)

- Signed message: **ASCII "ICTU-LP1-SCAN" ‖ credentialId ‖ nonce ‖ kioskId ‖ ts** (domain-separated from HCE).
- Online: `POST /me/scan { kind: "DEVICE_KEY", kioskId, nonce, ts, signature }`.
- Offline response QR (read by the kiosk webcam): `LPR1.<credentialId b64url>.<nonce b64url>.<ts decimal>.<signature b64url>`.

### 3.3 Passkey (web app)

- WebAuthn challenge = **SHA-256( ASCII "ICTU-LP1-PK" ‖ kioskId ‖ nonce )**. User verification is **required**.
- Online: `POST /me/scan/options` returns the request options, then `POST /me/scan { kind: "PASSKEY", kioskId, nonce, assertion }`.
- Offline response QR: `LPR2.<credentialId>.<nonce>.<authenticatorData>.<clientDataJSON>.<signature>` (all base64url).

## 4. Enrollment proof of possession

The new device key signs **ASCII "ICTU-LP1-POP" ‖ sessionId ‖ popNonce** (`popNonce` is 32 server bytes). Passkeys use the
WebAuthn registration ceremony, with `challenge = popNonce`.

## 5. Server acceptance rules

All of the following must hold:

1. The credential exists and is `ACTIVE`, and its student is not `INACTIVE`.
2. The signature or assertion verifies against the stored public key.
3. `GETDEL kc:{kioskId}:{nonce}` succeeds. This proves the challenge was issued to this kiosk, is unexpired (TTL 60 s) and is unused.
4. The kiosk is the caller: the device token for HCE and response QRs, or the target kiosk for `/me/scan`.
5. Clock skew: `|now − ts| ≤ 30 s` (HCE, kiosk clock) or `≤ 120 s` (device-key scan, phone clock). Passkey assertions have no timestamp; the challenge TTL bounds them.
6. Passkeys only: the rpId hash matches, the origin is on the allow-list, the UV flag is set, and `signCount` never decreases (when non-zero).

Error codes (problem+json `code`): `INVALID_SIGNATURE`, `UNKNOWN_CHALLENGE`, `STALE`, `CREDENTIAL_INACTIVE`, `MALFORMED`.

## 6. Change control

Any change to bytes, prefixes or rules requires a new version (`LP2`, AID `…02`) and new vectors. v1 phones must keep working until they are revoked.
